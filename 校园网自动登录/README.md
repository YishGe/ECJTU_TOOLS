# 校园网自动登录（Windows）

> 双击即连、开机自动连，**无浏览器、无窗口、无弹窗**的校园网认证小工具。
> 面向 **Dr.COM（城市热点）** 系列认证门户（登录页形如 `http://<认证服务器>/a70.htm`）。

## 特性

- **完全静默**：直接发 HTTP 请求复现登录表单，不启动浏览器、不弹窗、没有控制台窗口闪烁
- **双击即连**：`校园网登录.exe` 无参数运行 = 立即连接一次（失败自动重试）
- **开机自动连**：登录 Windows 后等待 N 秒（默认 6 秒）自动连接，失败按策略重试
- **图形化配置**：账号 / 密码 / 运营商 / 自启 / 延时 / 重试策略 / 062 处理方式 / 唤醒重连，全在界面上改
- **首次运行自动引导**：第一次双击 `校园网登录.exe` 而还没有 `config.ini` 时，会自动弹出配置工具
- **不会重复登录**：检测到已经能上网就直接跳过，避免在 AC 上累积多余在线会话
- **超限有提示**：认证返回 `code[062]`（同时在线设备数超限）时，自动打开自助服务平台并弹窗提醒你自行注销，处理完关掉提示即自动重试
- **零依赖、零安装**：单个 exe，只需系统自带 .NET Framework 4.x；不需要管理员权限，不装服务、不加计划任务
- **自动适应**：每次运行都从门户页读取当前分配到的 IP，换宿舍/换网段不用改配置
- **能 .exe 映射**：可绑定到鼠标侧键、宏按键、快捷键工具

## 适用前提

1. 认证门户是 **Dr.COM / 城市热点** 风格：打开门户页能看到 `/a70.htm`，表单字段是 `DDDDD`（账号）、`upass`（密码）、`0MKKey`（登录按钮）；
2. 有运营商选择的学校，是在账号后面拼后缀（`@telecom` / `@cmcc` / `@unicom`）；
3. 你的账号是"账号 + 密码"认证（不是扫码、不是短信验证码、不是网页 SSO）。

> 不确定？打开学校认证页按 F12 看提交的表单字段，或者先用浏览器登录一次抓个包对照。
> 字段不一致的话改 `src\LoginCore.cs` 里的 `PostLocal()` 即可。

## 快速开始

1. 双击 `校园网配置.exe`，填 **账号 / 密码**，选 **运营商**；
   把 `认证服务器` 改成你学校的认证门户地址（默认是占位值 `192.168.1.1`）；
2. 点 **立即测试登录** → 状态栏变绿并显示 `✔ 认证成功 …` 即成功；失败原因会显示在下方；
3. 点 **保存设置**（生成 `config.ini`），需要开机自动连就勾选 ☑ **开机自动登录**；
4. 把鼠标侧键/宏按键的"打开指定应用"指向 `校园网登录.exe`（**参数留空**）。

命令行也行：

```bat
校园网登录.exe           :: 立即连接（带重试）
校园网登录.exe --boot    :: 开机模式，先等 N 秒再连
```

## 工作原理

### 1. 取本机 IP

```
GET http://<认证服务器>/a70.htm
```

返回页里含脚本变量（每个会话不同）：

```js
v4serip='192.168.1.1';   vlanid="0";   ss5="10.x.x.x";
```

`ss5` 就是 AC 分配给本机的 IP，`vlanid` 是 VLAN 号。程序用正则取出它们，
所以**换网段、IP 变了都不用改配置**。

### 2. 提交登录表单（默认走 PORTAL 协议）

门户的登录/注销页里写明了它用的是哪种认证协议：

```js
authtype=1;                                        // 登录协议 = 1
authloginport=801;
authloginpath='/eportal/?c=ACSetting&a=Login';     // 真正的登录端点
authsuccess='Dr.COMWebLoginID_3.htm';
authfail='Dr.COMWebLoginID_2.htm';
```

所以 `认证方式=auto`（默认）会**先走 PORTAL 协议**：

```
POST http://<认证服务器>:801/eportal/?c=ACSetting&a=Login
     &protocol=http:&hostname=<认证服务器>&port=&iTermType=1
     &wlanuserip=<本机IP>&wlanacip=<AC地址>&wlanacname=<AC名称>
     &mac=<本机MAC>&ip=<本机IP>
     &redirect=&session=&enAdvert=0&queryACIP=0&loginMethod=1

DDDDD=<账号><运营商后缀>&upass=<密码>&R1=0&R2=&R3=0&R6=0&para=00&0MKKey=123456
&buttonClicked=&redirect_url=&err_flag=&username=&password=&user=&cmd=&Login=
```

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `wlanuserip` / `ip` | 门户页里的 `ss5` | 本机 IP，每次运行现取 |
| `wlanacip` | `AC地址` 配置项 | AC 的地址，空则提交 `null` |
| `wlanacname` | `AC名称` 配置项 | AC 名称，空则提交 `null` |
| `mac` | 本机网卡 MAC | **小写带横杠**，与页面 `getCurrMAC()` 输出一致 |
| `iTermType` | `1` | 终端类型：PC |
| `loginMethod` | `1` | PORTAL 协议 |

> **这几个参数缺一不可**。其中 `wlanacip` / `wlanacname` 来自 AC 劫持跳转的地址；
> `mac` 缺失或不匹配时，AC 会把会话记成一台 **MAC 全 0 的"假设备"**：
> 日志显示认证成功，但自助服务里看到的设备 MAC 是 `00-00-00-00-00-00`，
> 而且会白占一个"同时在线设备"名额，最终触发 `code[062]`。

如果 PORTAL 协议没成功（比如门户只开了本地认证），`auto` 模式会再退回 `a70.htm` 的本地认证：

```
POST http://<认证服务器>/a70.htm?wlanuserip=<本机IP>&wlanacip=<AC地址>&wlanacname=<AC名称>
     &vlanid=<VLAN>&ip=<本机IP>&ssid=null&areaID=null&mac=<本机MAC>
```

`认证方式=local` 只用本地认证，`认证方式=portal` 只用 PORTAL 协议。

> **回退是有条件的**：只有 PORTAL 端点**根本不可用**（连不上 / 返回 404）时才会退回本地认证。
> 如果 AC 明确拒绝了这次认证（例如返回 `RetCode=512`），程序只报错、不再绕道本地认证——
> 因为部分 AC 的本地认证**不校验密码**，会"成功"生成一台 MAC 全 0 的假设备，
> 白占一个同时在线名额，反而把账号拖进 `code[062]` 的死循环。

**运营商不是独立参数**，而是拼在账号后面（页面上"选择运营商"下拉框做的就是这件事）：

| 下拉框 | 实际提交的账号 |
| --- | --- |
| 中国电信 | `账号@telecom` |
| 中国移动 | `账号@cmcc` |
| 中国联通 | `账号@unicom` |
### 3. 结果判定

1. 先看返回页文字：`认证成功` / `已经在线` / `无需重复登录`；
2. 页面没给明确结论（例如返回一张"信息页"）时，用**"能不能上外网"兜底**
   （请求 `http://www.msftconnecttest.com/connecttest.txt`，拿到 `Microsoft Connect Test` 视为通网）；
3. 被明确拒绝时（密码错误 / 欠费 / 停机 …）**不会**被兜底误判成成功，日志会写明原因，
   同时把原始返回内容存到 `last_response.html`。

### 4. 重试与"已在线跳过"

每次尝试：

```
探测认证服务器（内网，很快） → [已在线则跳过] → 提交登录 → 判定结果
```

失败则等 `重试间隔秒` 再试，最多 `重试次数` 次。

开着 `已在线则跳过` 时，如果本来就能上网，程序**只发一个 GET，不提交任何认证**。
这一点很重要：反复认证会在 AC 上留下会话记录。

### 5. 认证服务器自动发现

如果配置的认证服务器暂时不通，程序会去读系统联网检测请求被劫持后的跳转地址
（`http://www.msftconnecttest.com/connecttest.txt` 等），从中解析真正的门户地址再试一次。

## `code[062]`：同时在线设备数超限

062 是 AC 侧的"该账号同时在线的设备太多"错误。程序**不会**替你登录自助服务、也**不会**自动注销任何设备
（误踢别的设备风险太大，且需要对第三方页面做逆向）。它的处理是：

1. 识别 062（正文里的 `<div id="message">Rad:Oppp error: code[062]…</div>`，
   或 302 跳转 `2.htm?…&RetCode=…&ErrorMsg=<base64>` 都能识别）；
2. **先判断本机是否其实能上网**——能上网就忽略 062，按成功处理；
3. 确实离线时：**打开自助服务平台**（`自助服务` 配置项）并**弹窗提醒**你：
   > 检测到校园网认证返回 code[062]：该账号的同时在线设备数已达上限。
   > 已为你打开自助服务平台：http://…
   > 请在该页面登录后，注销其他设备（或本机旧会话），然后点「确定」关闭本提示，程序会自动重试登录。
4. 你关闭提示后，程序按 `提醒后重试次数` / `提醒后重试间隔秒` 自动重新登录；
5. 仍失败则停止并退出（退出码 4），不会无限打扰。

## 开机自动登录

勾选后写入**当前用户**注册表（不需要管理员权限，不装服务、不加计划任务）：

```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
    CampusNetAutoLogin = "<路径>\校园网登录.exe" --boot
```

- 自启项在**用户登录后**执行——这也是 WLAN 关联、DHCP 拿到 IP 的最早时刻；
- Windows 在系统繁忙时可能再顺延几秒，属正常，脚本的重试机制会兜住；
- **移动文件夹后**：自启项里是绝对路径，只要再运行一次 `校园网登录.exe`（或打开配置工具），
  程序会自动把路径改成新位置，日志里会写"已更新开机自启路径为…"；
- 关闭：在配置工具里取消勾选即可（立即删除注册表项）；
- 状态栏红字提示"写入注册表失败"多为安全软件拦截，可尝试以管理员身份运行，或把文件夹加入白名单。

> **睡眠/休眠唤醒不会触发自启**。`HKCU\...\Run` 只在**登录 Windows** 时执行，合盖唤醒、休眠恢复都不会跑。
> 想让唤醒后也自动重连，在配置工具里勾选 ☑ **睡眠/休眠唤醒后自动重连** 即可：
> 程序会创建一个计划任务 `CampusNetAutoLogin_Wake`（触发器 = `System` 日志里 `Microsoft-Windows-Kernel-Power` 事件 `107`，
> 即"从睡眠恢复"；以当前用户身份、最低权限运行，不需要管理员、不需要密码），取消勾选就删除。
> 如果创建失败（被安全软件拦截），可按同样参数在「任务计划程序」里手动建一个。

## 日志与排错

看 `login.log`；失败时再看 `last_response.html`（已转 UTF-8，可直接用浏览器打开）。

| 日志提示 | 含义 | 处理 |
| --- | --- | --- |
| `认证成功 10.x.x.x（账号@telecom）` | 成功 | — |
| `当前已在线，跳过登录` | 网络本来就通 | 正常 |
| `无法访问认证服务器（网络可能还没连上）` | 门户都连不上 | 检查是否连上校园网；等重试 |
| `密码错误` / `用户名或密码错误` | 密码不对 | 改密码 |
| `余额不足` / `已欠费` / `账号已停机` | 账号欠费 / 停机 | 去学校自助服务平台处理 |
| `认证系统返回错误码 code[062]` | 同时在线设备超限 | 见上一节，按提示在自助服务里注销设备 |
| `认证系统返回错误码 code[512]` | AC 明确拒绝（常见于设备超限/会话残留/参数不被接受） | 去自助服务平台注销设备后再试；不要用本地认证绕 |
| `PORTAL 协议被 AC 拒绝，不再退回本地认证` | 程序主动阻止了"假设备"路径 | 正常保护行为，按上一条处理 |
| `认证页未给出明确结果，但网络已可访问` | 返回信息页但实际已通 | 视为成功 |
| 自助服务里出现 `00-00-00-00-00-00` 的设备 | 登录时 MAC 没被 AC 采纳，被记成假设备 | 注销掉它；看日志"本机 MAC："与"捕获到 AC 劫持跳转地址"；必要时设 `本机MAC=` / `AC地址=` / `AC名称=` |

## 常见问题

**Q：换运营商 / 改密码？**
配置工具里改完保存即可。运营商对应账号后缀，见上文表格。

**Q：学校换了门户 IP？**
先不改试一次（有自动发现）。不行就把 `认证服务器` 改成新地址。

**Q：会不会把我正在用的网络踢掉？**
默认不会。程序先判断能不能上网，能上就直接跳过，不提交认证。062 场景下它也不会注销任何设备。

**Q：为什么不自动帮我注销 062 的超限设备？**
注销需要对学校自助服务平台做登录与批量操作，一旦接口理解错就可能把你自己或别人的设备踢下线。
本工具选择"打开页面 + 明确提醒"，把决定权留给人。

**Q：为什么不做成开机 0 秒 / Windows 服务？**
用户会话里的 WLAN/DHCP 还没就绪时登录必然失败；服务方式还要管理员权限、卸载也麻烦。
"登录后 6 秒 + 失败重试"覆盖面最好、权限要求最低。

**Q：杀毒软件报警？**
本地编译、无数字签名的 exe，个别杀软会提示"未知程序"，加白名单即可。源码在 `src\`，可自行编译核对。

**Q：能用在手机上吗？**
不能，这是 Windows 桌面程序（.NET / WinForms）。

## 隐私与安全

- **不联网上传任何东西**：只访问三处——① 你配置的学校认证服务器；② 062 时打开的自助服务页面；
  ③ 系统联网检测地址（`www.msftconnecttest.com` / `connect.miui.com`，仅用于判断"是否已经能上网"）。
  没有统计、没有更新检查、没有第三方接口。
- **不读浏览器数据、不抓包、不装驱动、不改网络适配器/代理设置**，也不会操作自助服务平台里的设备。
- 唯一的系统写入：那条**当前用户**的注册表自启项（可在界面一键关闭）。
- 账号密码保存在本地 `config.ini`；`b64:` 只是简单编码防旁人瞄一眼，**不是加密**。
  `config.ini` 已在 `.gitignore` 中，**提交代码前务必确认没有把自己的配置和日志提交上去**。
- 请仅用于自己的账号，并遵守所在学校的网络使用规定。使用风险自负。

## 从源码编译

`src\` 内容：

| 文件 | 内容 |
| --- | --- |
| `LoginCore.cs` | 核心：配置读写、HTTP 登录、结果判定、重试、062 处理、日志、注册表自启 |
| `LoginApp.cs` | `校园网登录.exe` 入口 |
| `ConfigApp.cs` | `校园网配置.exe`（WinForms 界面） |
| `app.manifest` | `asInvoker`（不需要管理员）+ 系统 DPI 感知 |
| `build.ps1` | 用系统自带 `csc.exe` 一键编译，无需安装 .NET SDK |

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\src\build.ps1
```

依赖：Windows 自带的 .NET Framework 4.x（Win10/11 默认具备），无第三方库。
